# 数据检索策略（多平台通用）

## 一、核心原则

**数据必须来自实时检索，禁止凭记忆编造行情数据。** 所有关键数据需标注**来源 + 时点**（YYYY-MM-DD 或 YYYYQn）。

## 二、多平台工具映射

不同 AI agent 平台的数据检索工具不同，按当前环境选择**第一优先级可用工具**：

| 优先级 | 数据类型 | WorkBuddy | Claude / GPT / 其他 |
|---|---|---|---|
| **1** | 行情/指数/资金 | 金融 MCP（NeoData 等）| 联网搜索 / 财务数据插件 / API |
| **2** | 综合检索（资讯+行情） | `domain_search` 工具 | 联网搜索（Web Search）|
| **3** | 公开信息兜底 | `WebSearch` | 联网搜索 / 用户提供的数据 |

**降级必须逐级进行并说明原因，禁止跳级。**

### WorkBuddy 环境
1. 优先使用金融类 MCP（NeoData 等）
2. 不可用时降级至 `domain_search`
3. 仍不可用时用 `WebSearch`

### Claude / GPT / 其他 Agent 环境
1. 优先使用联网搜索 / 财务数据插件（如 ChatGPT 的 Code Interpreter + 联网）
2. 无联网能力时，可要求用户提供行情数据或使用工具调用（如 API）
3. 所有数据标注来源，无来源数据标"待核实"

### 纯对话环境（无检索能力）
- 明确告知用户当前环境无法获取实时数据
- 可基于用户提供数据进行分析
- 不凭记忆编造行情数字

## 三、检索 query 模板（通用）

无论什么平台，检索意图一致，按以下 query 发起：

**调用 1（指数面 + 市场状态）**：
```
分析最近一周 A 股市场整体走势和市场状态（上证指数、深证成指、创业板指涨跌、成交额、市场广度、涨跌家数）
```

**调用 2（结构面 + 主线资金）**：
```
分析最近一周 A 股市场热点板块轮动、市场主线题材和资金流向情况
```

- 两次检索**并行发起**
- 用户指定时间范围时（如"最近一个月"），替换 query 中的时间词
- **禁止**将 query 拆成多维度字段清单（如"请查询涨跌幅、成交额、涨跌家数……"），保持一句话检索意图

## 四、数据时效校验

拿到数据后**必须核对统计周期和截止时间**：

| 情况 | 处理 |
|---|---|
| 数据覆盖目标周期 | 按实际周期使用，标注时点 |
| 当前周期尚未发布 | 使用最近已发布周期，明确说明数据截止时间 |
| 数据明显早于目标周期 | 调整参数或换源重新查询 |
| 仍无法获取 | **明确声明数据缺口**，禁止把历史数据表述为当前数据 |

### 时间口径

- **相对时间默认北京时区**："今天 / 昨天 / 本周"按北京时间
- **交易状态**：回答"最新 / 今天"前先确认是否在交易时段。盘中标注"截至 XX:XX"
- **跨市场对比**：A 股 T 日收盘 / 美股 T-1 夜盘不是同一时点，点明对齐口径

## 五、来源标注规则

### 来源质量分级

| 级别 | 来源类型 | 处理方式 |
|---|---|---|
| **一手** | 交易所公告、统计局、公司年报/季报、央行/监管 | 直接采信，标注机构名 + 发布日期 |
| **非一手** | 财经媒体、研报引用、第三方数据平台 | 标注"需核实原文"，不得与一手来源同等处理 |

### 标注粒度

- 同一数据块共享来源、周期、口径 → 在表头/表尾统一标注
- 不同子项来源不同时 → 分别标注
- 网络搜索兜底 → 标媒体名 + 日期 + 原文链接（如有）

## 六、交叉验证

同一指标不同来源给出不同数值时：
1. 至少列两个来源
2. 优先采信交易所 / 公司公告 / 年报等一手来源
3. **显式说明分歧**，不要静默选一个
